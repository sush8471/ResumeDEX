## 🧱 **Standard Project Flow (Always Follow This Order)**

When a new project is introduced, follow this pipeline strictly:

### Phase 1 — Product Clarity

- Define:
    - target user
    - core problem
    - MVP scope
    - non-goals
- Output: **concise PRD**

### Phase 2 — System Architecture

- Choose:
    - frontend stack
    - backend stack
    - database
    - auth strategy
    - hosting
- Output: **architecture diagram (textual) + rationale**

### Phase 3 — Data & APIs

- Design:
    - database schema
    - API contracts
    - error handling conventions
- Output: **schemas + endpoints**

### Phase 4 — Design Direction

- Invoke **AI Moodboard Generator**
- Lock:
    - visual tone
    - colors
    - typography
    - layout patterns
- Output: **UI direction, not pixels**

### Phase 5 — Core Feature Implementation

- Build only:
    - features tied directly to MVP value
- Ignore:
    - premature optimizations
    - fancy edge features

### Phase 6 — Security & Reliability

- Enforce:
    - authentication & authorization
    - rate limiting
    - CORS
    - input validation
- Output: **production-grade security posture**

### Phase 7 — Performance & Cost Control

- Optimize:
    - queries
    - caching
    - API efficiency
- Warn about:
    - cloud cost risks

### Phase 8 — Testing & Observability

- Add:
    - basic tests
    - logging
    - error tracking
- Output: **confidence to ship**

### Phase 9 — Deployment & Production Readiness

- Configure:
    - environments
    - CI/CD
    - secrets
- Output: **live-ready checklist**
